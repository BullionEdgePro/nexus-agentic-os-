# Team chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A team room and 1-to-1 direct chats for each business's staff, live, private to the business, readable by the admin.

**Architecture:** Three tenant-scoped tables (migration 101) behind one access function; a flat `/api/team-chat` route scoped inside its handlers; events on a second Redis channel delivered through a `/ws/team` path on the existing WebSocket server; one deck page plus a sidebar badge, an @mention alert and an inbox "Ask a colleague" picker.

**Tech Stack:** Postgres (RLS), Hono, ioredis pub/sub, ws, Next.js (app router), node:test.

**Spec:** `docs/superpowers/specs/2026-10-24-team-chat-design.md`

## Global Constraints

- Body 1–4000 characters, trimmed; empty after trim is refused (400 "Write a message first.").
- Refusals of access answer 404 `{ error: "Not found" }`.
- Every database call in the route runs inside `withTenant(organizationId)`; `processor.ts` is untouched.
- Staff are re-checked against `is_active` on every request.
- Copy: "Team chat", "Your admin can read team chats.", "Sending…", "Not sent · Retry", "Message removed", "Read only — between {a} and {b}", "Gives {name} access to this chat", "Ask a colleague".
- Migration applied on the server as the owner role before the code is deployed.

## Review Focus

- A retried send after a timeout (same clientId) must not create a second message → test in Task 2.
- A staff member removed from the team while their tab is open must be refused on the next request → test in Task 2.
- A direct chat requested with someone from another business, or with oneself → 404, test in Task 2.
- An @mention naming someone outside the thread's business is dropped, not stored → test in Task 2.
- The socket drops while a message is in flight: the screen shows "Not sent · Retry" and resends with the same clientId → test in Task 4.

**Interfaces — Produces (packages/db/src/team-chat.ts):**
- `type TeamViewer = { kind: "staff"; employeeId: string; organizationId: string } | { kind: "admin"; adminId: string; name: string }`

- `teamAccess(thread: TeamThread, viewer: TeamViewer): { read: boolean; post: boolean }` (pure)

- `teamUnread(organizationId | null, viewer): Promise<{ unread: number; mentioned: number }>`
